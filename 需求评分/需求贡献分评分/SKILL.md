# 需求贡献分评分

从 PRD/TRD 需求文档中客观计数 → 规则引擎套公式计算 → 人只做复核。

## 核心原则

规则固定、输入客观、过程可复现、结果可审计。每一步都可被开发者手动验算。

---

## 分成公式

**开发者分成比例 = 该开发者完成需求的贡献分之和 ÷ 该软件产品所有需求的贡献分总和**

所有需求（功能型、研发型、混合型）汇入同一个分成池，使用统一的 Fibonacci 贡献分。

---

## 需求分类

| 类型 | 输入文档 | 特征 | 评分方式 |
|------|---------|------|---------|
| **功能型** | PRD | 功能/页面/规则可枚举，需求确定 | 三维客观计数 |
| **研发型** | TRD | 涉及算法选型/模型训练/数据工程，有不确定性 | 三维计数 + 不确定性系数 |
| **混合型** | PRD + TRD | 同时包含功能和研发两部分 | 分别计分后合并 |

---

## 功能型需求评分

### 维度一：功能广度（权重 40%）

| 计数项 | 分值 | AI 识别依据 |
|--------|------|------------|
| 功能模块/子功能（末级节点） | 3 分/个 | 功能结构图末级节点 |
| 独立页面 | 2 分/个 | 页面清单、路由表 |
| 弹窗/抽屉 | 1 分/个 | 模态组件描述 |
| 用户角色 | 2 分/个 | 权限矩阵中的角色 |
| 外部系统对接 | 3 分/个 | "对接XX系统"、"调用XX服务" |

### 维度二：业务逻辑深度（权重 35%）

| 计数项 | 分值 | AI 识别依据 |
|--------|------|-------------|
| 状态节点 | 1 分/个 | 状态机图中的状态 |
| 业务校验规则 | 1 分/条 | "校验/判断/验证/约束/限制"引导的条目 |
| 分支/异常路径 | 1 分/条 | 流程图中判断节点，异常处理路径 |
| 计算公式/业务算法 | 2 分/个 | PRD 中明确给出的公式 |

### 维度三：数据结构复杂度（权重 25%）

| 计数项 | 分值 | AI 识别依据 |
|--------|------|-------------|
| 业务实体 | 2 分/个 | 信息结构图中的实体 |
| 实体字段 | 0.3 分/个 | PM 列出的实体字段 |
| 实体关联关系 | 1 分/1:1，1.5 分/1:N，2 分/N:M | 实体间关联描述 |

### 变更系数

| 变更类型 | 系数 | 判定标准 |
|----------|------|----------|
| 新增 | ×1.0 | 从无到有创建 |
| 修改 | ×0.3 | 存量内容调整 |
| 删除 | ×0.1 | 移除/下线 |

每一项得分 = 数量 × 基准分 × 变更系数。变更系数已乘入各项小计。

### 功能型公式

```
功能原始分 = 维度一 × 0.40 + 维度二 × 0.35 + 维度三 × 0.25
```

---

## 研发型需求评分

### 维度一：算法与技术规模（权重 40%）

| 计数项 | 分值 | AI 识别依据 |
|--------|------|------------|
| 候选算法/模型选型 | 8 分/个 | "需评估/对比 XX 与 YY" |
| 算法流水线阶段 | 5 分/阶段 | 每个独立处理阶段 |
| 算法评价指标 | 1 分/个 | Accuracy, mAP, F1, Recall 等 |
| 自定义模型组件 | 8 分/个 | 自定义层、损失函数、训练策略 |
| 论文复现或算法创新 | 15 分/项 | 需复现论文或提出新方案 |

### 维度二：数据工程规模（权重 35%）

| 计数项 | 取值方式 | 分值 |
|--------|---------|------|
| 数据集规模 | 微型<1K / 小型1K-1万 / 中型1万-10万 / 大型10万-100万 / 超大>100万 | 2 / 5 / 10 / 18 / 28 |
| 标注复杂度 | 无标注 / 简单标签 / 检测框/分割 / 需专家标注 | 0 / 4 / 10 / 20 |
| 数据预处理/增强步骤 | 每步 3 分 | 清洗、归一化、翻转等 |
| 数据质量治理项 | 每项 5 分 | 类别不均衡、噪声清洗等 |

### 维度三：工程化要求（权重 25%）

| 计数项 | 分值 | AI 识别依据 |
|--------|------|------------|
| 模型压缩/加速 | 5 分/项 | 量化、剪枝、蒸馏、TensorRT 等 |
| 监控与持续迭代 | 3 分/项 | 训练监控、推理质量监控、漂移检测等 |

### 研发不确定性系数

| 评估维度 | 低（×0.7） | 中（×1.0） | 高（×1.5） | 极高（×2.0） |
|----------|-----------|-----------|-----------|------------|
| 技术成熟度 | 成熟方案可直接复用 | 有开源参考，需适配 | 仅有论文，需复现 | 全新问题，无参考 |
| 效果达标难度 | 达到 baseline 即可 | 达到行业平均 | 达到/超越 SOTA | 定义新 SOTA |
| 预期探索轮次 | 1-2 轮 | 3-5 轮 | 6-10 轮 | 长期探索 |

**不确定性系数 = (技术成熟度 × 效果达标难度 × 探索轮次) ^ (1/3)**，几何平均。由 Tech Lead 锚定。

### 研发型公式

```
研发原始分 =（维度一 × 0.40 + 维度二 × 0.35 + 维度三 × 0.25）× 不确定性系数
```

---

## 混合型需求

```
综合原始分 = 功能原始分 + 研发原始分 × 0.8
```

研发部分乘 0.8 因功能侧的页面/接口部分复用了研发产出，存在少量工作量重叠。

---

## 统一 Fibonacci 映射表

| 原始分 | 贡献分 | 等级 | 参考工作量 |
|--------|--------|------|-----------|
| 0 - 10 | 1 | XS | ≤ 0.5 天 |
| 11 - 22 | 2 | S | 0.5 - 1.5 天 |
| 23 - 40 | 3 | S+ | 1.5 - 3 天 |
| 41 - 65 | 5 | M | 3 - 6 天 |
| 66 - 95 | 8 | L | 1.5 - 2.5 周 |
| 96 - 130 | 13 | XL | 2.5 - 4 周 |
| 130+ | 20（强制拆分） | XXL | > 1 月 |

> ⚠️ 原始分超过 130 时，必须拆分为 2 个以上子需求分别评分。

## 双版本评分规则（必须执行）

**每次评分默认生成版本 A 和版本 B，并输出对比表。**

### 版本 A：算前端（全量）

包含所有功能节点、UI 交互、页面、弹窗、前端状态、前端校验、前端异常路径、UI 相关实体字段。

### 版本 B：不算前端（纯后端逻辑）

剔除以下纯 UI/前端内容：
- UI 渲染与 DOM 交互
- Canvas/图表绘制
- CSS 样式/动画
- 导航/路由切换
- 视觉状态指示（loading 动画、进度条等，除非对应后端状态机节点）
- Markdown/文本格式化输出
- 弹窗/抽屉 UI 组件
- Appium/Playwright/Selenium 等 UI 自动化操作
- 移动端元素定位/点击/滑动/截图等操作
- 纯前端表单校验（仅在前端执行的校验）
- 纯 UI 实体字段（color、cls、布局属性、WebElement 引用、屏幕坐标等）

保留：数据模型、业务算法、校验规则（后端）、API 调用、数据持久化、导入导出、CLI 命令核心逻辑、配置管理、Docker 容器编排、打包构建、测试体系。

### 对比表格式

```
| | 版本 A（算前端） | 版本 B（不算前端） | 差值 |
|---|---|---|---|
| 功能末级节点 | N | M | −X |
| 独立页面/弹窗 | N + M | 0 + 0 | −X |
| 状态节点 | N | M | −X |
| 校验规则 | N | M | −X |
| 分支/异常路径 | N | M | −X |
| 实体字段 | N | M | −X |
| **原始分** | **X.XX** | **Y.YY** | −Z |
| **贡献分** | **N（等级）** | **M（等级）** | |
| **参考工作量** | **X** | **Y** | |
```

## 多人项目开发者贡献分拆解

当需求涉及多个开发者时（从 git 提取），评分文件必须包含开发者贡献分拆解章节。

### 开发者识别

```bash
# 提取所有贡献者
git log --format='%an' | sort -u

# 按文件统计贡献
git log --format='%an' -- <file_or_directory>

# 按行归属
git blame <file>
```

### 模块-开发者映射

从 devlog、git history、代码目录结构推断每个开发者负责的模块。

### 贡献分拆解规则

1. 将功能末级节点按开发者分组
2. 每个开发者的贡献分 = 该开发者负责模块的维度加权得分 → 除以总分的比例 × 总贡献分
3. 多人共同负责的模块，默认均分

### 输出格式

```markdown
## 开发者贡献分拆解

| # | 开发者 | 负责模块 | 模块原始分占比 | 贡献分 |
|---|--------|---------|--------------|--------|
| 1 | xxx | CLI框架+配置系统 | 35% | 5 (M) |
| 2 | yyy | 容器运行时+代理 | 30% | 3 (S+) |
| 3 | zzz | 打包+测试 | 20% | 2 (S) |
| 4 | www | 文档+工具 | 15% | 2 (S) |
| **总计** | | | **100%** | **13 (XL)** |
```

**约束：**
- 开发者贡献分之和 ≈ 总分（允许因取整略有偏差，偏差应 < 1 分）
- 每个开发者的模块归属需列出具体功能节点（见附件）
- 如无法从 git 准确判断分工，标注 `<!-- 待确认 -->` 等待开发者复核

---

## 评分流程

```
PRD / TRD 文档（或反推后签认的需求文档）
  → Step 1: AI 提取对应维度的计数项（逐项附原文依据）
  → Step 2: 规则引擎套公式算分（纯代码，不涉及 AI）
  → Step 3: 生成版本 A（算前端）和版本 B（不算前端）对比
  → Step 4: 如有多个开发者，提取 git 分工，拆解每人贡献分
  → Step 5: 研发型需求由 Tech Lead 复核不确定性系数
  → Step 6: 公示 48h（展示分数 + 每项计数依据 + 不确定性定级理由）
  → Step 7: 开发者可申诉，评审委员会裁定
  → Step 8: 锁定分数，计入当期分成
```

**关键约束：**
- AI 只读 PM/Tech Lead 的产出文档，不涉及数据库设计、技术选型等开发者决策
- 规则引擎是确定性代码，同一输入永远得同一输出
- 每项计数均附带原文依据，可逐项复核

---

## 有效性交叉验证

评分完成后必须执行交叉验证：

| 验证项 | 方法 |
|--------|------|
| 自写代码行数 | 排除第三方后的代码总行数 |
| 第三方代码体量 | 排除目录的大小/文件数 |
| 代码中 UI 操作占比 | 前端相关代码行数 / 总行数 |
| A 版贡献分 vs 体感 | 贡献分对应的工作量是否与代码规模吻合 |
| B 版贡献分 vs 体感 | 剔除前端后的核心逻辑工作量是否吻合 |
| 与其他项目评分对比 | 横向对比类似规模项目的评分，防止评分漂移 |

## 争议处理

开发者只能申诉**事实性计数错误**：

| ✅ 可申诉 | ❌ 不可申诉 |
|----------|------------|
| "AI 漏数了第 3 页的 1 个接口" | "我觉得分数应该更高" |
| "AI 把修改判为新增，PRD 写的是'优化'" | "上次那个需求更简单分却更高" |
| "AI 少计了 2 条校验规则" | "修改系数 0.3 太低了" |
| 研发型："AI 漏数了候选算法对比项" | 研发型："为什么同是目标检测上次分更高" |
| 研发型："AI 把 50 万判为大型，实际 8 万应为中型" | 研发型："不确定性系数 0.7 太低了" |
| 研发型："Tech Lead 定级与锚定标准明显不符" | — |
| "开发者分工归属错误" | "为什么我的贡献分比他低" |

申诉须附带原文引用，评审委员会 24h 内裁定。**连续 3 次驳回冻结 1 个结算周期。**

---

## 参数管理

- 所有参数（基准分、变更系数、维度权重、分级表、不确定性锚定标准、映射表）写入制度文件
- 每季度回顾偏差，触发调整需 ≥ 2/3 核心开发者投票通过
- 每半年最多修订一次，新参数从下一周期生效，**不追溯**
- 上线前用 20-30 个历史需求做双轨试运行，偏差在 ±25% 以内方可启用

---

## 评分文件输出格式

评分文件必须包含以下章节：

1. **元数据**：评分依据、需求文档路径、评分日期
2. **反推流程状态**（如适用）：Step 1-3 状态
3. **需求分类**：类型 + 变更类型 + 评分方式
4. **版本 A 详细计算**：三维度明细 + 综合计算 + 等级映射
5. **版本 B 详细计算**：剔除标准说明 + 三维度明细 + 综合计算 + 等级映射
6. **两版本对比表**
7. **开发者贡献分拆解**（多人项目必须）
8. **有效性交叉验证**
9. **附件**：功能末级节点明细、状态节点明细、校验规则明细、分支/异常路径明细、计算公式明细、业务实体与字段明细
